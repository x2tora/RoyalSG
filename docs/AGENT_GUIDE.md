# 로얄상구 에이전트 인수인계 가이드

기준일: 2026-11-08. 구현 구조와 작업 중 확인한 주의점을 정리한 문서다. 운영 환경의 현재 상태나 무결함을 보증하는 자료가 아니다. 버전은 `package.json`과 lockfile, DB 동작은 모든 마이그레이션을 순서대로 반영한 결과를 확인한다.

## 1. 작업 원칙

- 사용자에게 가정과 변경 범위를 먼저 설명한다. 불명확한 요구가 결과에 영향을 주면 확인한다.
- 요청 밖의 리팩터링·문구 변경·의존성 교체를 하지 않는다. 기존 한국어 문체와 Material 3 디자인을 따른다.
- 사용자는 임의의 홍보성 문구를 원하지 않는다. 안내 문구를 보존하라는 요청이 있으면 내용은 그대로 두고 구조만 바꾼다.
- 진행 상황과 결과는 한국어로 간결하게 전달한다. 커밋 메시지도 한국어로 쓴다.
- 사용자에게 검증 생략 요청이 있으면 임의의 전체 테스트나 브라우저 검증을 추가하지 않는다. 실행한 검사와 하지 않은 검사를 구분한다.
- `git status`와 현재 변경을 먼저 확인한다. 첨부 파일·기존 작업·비밀 설정을 임의로 삭제하거나 커밋하지 않는다.
- 반복된 구현 관행만으로 새 요청의 운영 DB 변경·배포 권한까지 추정하지 않는다. 현재 대화의 승인 범위를 따른다.

## 2. 제품과 운영 상태

모바일 중심의 로얄상구 기기 대여 예약 서비스다. 온라인 결제는 없다.

**현재 소스는 잠정 중단 배너를 표시하지만, 예약 기능 자체는 활성화되어 있다.**

- 중단 안내를 넣으며 신규 예약을 UI·API·DB에서 차단한 뒤, 사용자가 배너만 유지하고 기능은 복원하도록 요청했다.
- `20261106234821_suspend_new_bookings.sql`만 보고 예약이 차단된 상태라고 판단하지 않는다.
- 뒤의 `20261107152508_restore_new_bookings.sql`이 생성 함수를 복원한다.
- 배너를 제거하거나 예약을 다시 차단하는 변경은 별도 요청 없이 하지 않는다.

Next.js App Router, React, TypeScript, `@material/web`, Supabase SSR, Vercel을 사용한다. Outfit·Pretendard JP 폰트를 자체 호스팅한다.

Next.js API를 수정하기 전에 설치된 `node_modules/next/dist/docs/`의 관련 문서를 읽는다. 다른 Next 버전의 기억에만 의존하지 않는다.

## 4. 예약·계정 규칙

- 날짜 판정은 서버 한국 시간 기준이다. 예약 날짜 다음날 00:00~05:00에 이용한다.
- 예약 날짜 기준 일·월·화·수·목 운영, 당일 예약 불가.
- 21시 전에는 내일~13일 뒤, 21시부터 내일~14일 뒤까지 신청 가능.
- 하루 A/B/C 중 한 기체만 대여한다. 1인 25,000원, 2인 35,000원이며 금액은 서버에서 결정한다.
- 대기·확정 모두 날짜와 계정당 진행 예약 1건 한도를 선점한다. 실제 이용 종료 후 한도를 해제한다.
- 승인 대기는 본인이 직접 취소할 수 있고 5일 제한을 적용하지 않는다. `cancelled_by_self`로 “본인 취소”를 구분한다.
- 확정 예약 취소는 예약일 5일 전까지 문의로 요청하고 관리자가 처리한다.
- 진행 예약이 있으면 예약일 5일 전까지 탈퇴 가능, 4일 전부터 실제 이용 종료 전까지 탈퇴 제한.
- 본인 취소 후 탈퇴 가능한 것은 현재 요청된 동작이다. 이를 탈퇴 제한 우회라고 보고 임의로 막지 않는다.
- 가입 취소는 가입 완료 전 계정만 허용한다. 완료된 회원의 탈퇴 절차와 섞지 않는다.
- 탈퇴 시 예약 개인 연결정보·세션·Auth 사용자 등을 정리한다. 일반 보유 예약의 개인 연결정보는 실제 종료 후 90일 기준으로 정리한다.
- 신청·승인·취소·거절 시각을 보관한다. 추가 이전의 처리 시각은 추정하지 않고 “기록 없음”으로 표시한다.

## 5. DB 보안 경계

- UI의 비활성화·숨김은 권한 검사가 아니다. 직접 API/RPC를 호출해도 DB에서 동일 규칙을 검사해야 한다.
- 노출된 `public` RPC는 invoker wrapper, 권한이 필요한 구현은 `private`의 definer 함수다. 빈 `search_path`와 명시적 권한을 유지한다.
- `private`는 무조건 실행 불가능한 스키마가 아니다. wrapper 실행에 필요한 USAGE·EXECUTE가 있으므로 함수 내부 검증이 중요하다.
- 프로필·예약 조회 RLS는 본인 UID와 활성 세션을 확인한다. 직접 테이블 쓰기는 허용하지 않는다.
- 민감한 동작은 JWT 존재만 보지 않고 `session_id`를 `auth.sessions`와 대조한다. 삭제·로그아웃 뒤 남은 JWT를 고려한다.
- 보호된 mutation은 검증된 Google identity를 요구한다. 사용자 수정 가능 `user_metadata`를 권한 근거로 쓰지 않는다.
- 관리자 권한은 `private.admins`가 기준이다. 현재는 DB에서만 추가·제거하며, 특정 이메일의 자동 재부여는 제거했다. 관리 SQL은 README에 있다.
- 예약 생성·승인·차단·취소·탈퇴·정리의 공통 transaction advisory lock `783021`과 active 날짜/사용자 unique index를 보존한다.
- 공개 캘린더에는 날짜·기체·인원·상태만 제공한다. 이름·전화번호·회원 ID를 노출하지 않는다.
- API mutation의 동일 Origin 검사와 고정 command map을 유지한다. 사용자 입력을 임의의 RPC 이름으로 사용하지 않는다.
- publishable key와 사용자 세션으로 동작한다. service-role 키를 프런트나 `NEXT_PUBLIC_*`에 추가하지 않는다.

마이그레이션은 기존 파일을 고치는 대신 새 파일을 만들어 순서대로 적용한다. 공개 함수에서 private로 옮겨진 이후의 변경은 **실제 구현이 있는 private 함수**에 적용한다. DB 변경을 승인받았다면 적용 후 제한된 읽기 쿼리 등으로 결과를 확인하고, 소스 파일 작성과 운영 DB 적용을 구분해 보고한다.

## 6. UI·접근성 원칙

- Material Web 버튼·아이콘 버튼·입력·선택·체크박스를 사용한다. Google 로그인 버튼은 흰색 브랜드 디자인을 유지한다.
- 아이콘은 24px, 닫기 등 아이콘 버튼의 터치 영역은 48px를 기준으로 한다. 문자 `×` 대신 SVG를 사용한다.
- 모바일에 마우스 hover 배경이 남지 않게 CSS hover는 `(hover: hover) and (pointer: fine)`에서만 적용한다.
- 터치 기본 하이라이트는 투명, 텍스트 선택은 서비스 테마 색상이다. Material ripple과 브라우저 탭 하이라이트를 혼동하지 않는다.
- 텍스트 복사·선택은 막지 않는다. 이미지에만 저장 메뉴·드래그 방지가 있으며 완전한 저장 차단 기능은 아니다.
- 캘린더 상태는 예약 가능 초록 / 제한 기존 중립색 / 대기 연한 보라 / 확정 진한 보라다. 테마별 글자 대비를 유지한다.
- 날짜 아래 첫 줄은 상태, 둘째 줄은 `A 기체 · 2인`이다. 범례와 날짜 색상을 함께 수정한다.
- 월마다 안쪽 여백을 유지해 오늘 outline이 잘리거나 옆 월과 붙지 않게 한다. 스크롤 계산은 월 viewport 폭 기준이므로 별도 gap을 넣으면 계산도 조정해야 한다.
- 달력은 네이티브 수평 스크롤·scroll snap을 사용한다. 포인터 임계치로 달을 강제로 바꾸는 방식으로 회귀하지 않는다.
- 메인은 현재 예약만 표시한다. 관리자는 현재 예약을 기본으로, 이전 내역은 별도로 보며 신청 시각 최신순이다.
- 이용 안내 카드는 예약·조회에서만 표시한다. 관련 항목 묶음과 구분선을 유지한다.
- 테마와 저시력 모드는 현재 페이지를 이동시키지 않는다. 저시력 설정은 저장되고 개인정보 처리방침에도 적용된다.
- 저시력 모드에는 큰 글자·버튼·고대비·포커스 표시를 유지하고 모션을 생략한다. 개인정보 표는 확대 시 가로 스크롤 영역으로 제공한다.
- 정책 페이지를 공통 화면 밖으로 분리하면 테마 재초기화와 헤더 전환 문제가 다시 생길 수 있다.

## 7. 모션·상태 피드백에서 배운 점

- 첫 탭 세션의 중앙 로고 인트로를 유지한다. 리소스 준비 전 시작하지 않고, 새로고침에서 중앙 로고가 먼저 깜빡이지 않도록 초기 스크립트와 CSS 조건을 함께 살핀다.
- 홈↔다른 화면의 헤더 크기 전환과 테마 아이콘 회전은 사용자 요청으로 유지 중이다.
- 컴포넌트 등장·퇴장은 기본적으로 opacity만 바꾼다. 바운스·슬라이드·확대 효과를 새로 넣지 않는다.
- 동의 안내의 펼침/접힘은 예외적으로 높이를 부드럽게 바꾸고 내용을 페이드한다.
- 5개 동의 완료 시 400ms 후 자동 접힘. 다시 열어 수정할 수 있고, 기체·인원 변경 시 동의를 초기화하고 안내를 다시 연다.
- Web Animations API의 `fill: forwards`를 취소하면 원래 opacity로 돌아간다. 팝업 닫기에서는 dialog를 실제로 닫기 전에 애니메이션을 취소하면 깜빡일 수 있다.
- rAF는 초기화·시작 시점 조정에 사용한다. CSS/Web Animations API가 60fps로 고정된 것은 아니다. 실제 기기 측정 없이 120/165fps를 보장하지 않는다.
- 고주사율 개선을 위해 헤더를 FLIP/transform으로 바꿨다가 사용자가 기존 방식으로 복원을 요청했다. 측정·합의 없이 다시 도입하지 않는다.
- 페이지별 Home 재마운트는 데이터 재조회·인트로 재시작·헤더 깜빡임을 유발했다. 공통 인스턴스를 유지한다.
- 테마 색상은 초기 CSS 토큰과 root dataset으로 적용한다. 마운트 후에만 색상을 계산해 입히면 초기 깜빡임이 발생할 수 있다.
- 완료 알림은 고정 위치에 표시한다. 문단 삽입으로 저장 버튼이나 폼이 밀리게 하지 않는다.
- 입력 오류와 동의 상태는 공간을 미리 확보한다. 문구 교체나 알림 만료가 예기치 않은 레이아웃 이동을 만들지 않게 한다.
- 마이페이지 저장 후 현재 화면 유지, 예약 접수 후 카드 강조, 팝업 종료 후 날짜 포커스 복귀를 보존한다.
- 드롭다운은 바깥 스크롤에서 닫고 내부 항목 스크롤은 유지한다. 현재 Material Web의 shadow `md-menu.close()`를 사용하므로 라이브러리 업데이트 시 이 연결을 확인한다.
- 탈퇴 최종 확인은 실수 방지를 위해 의도적으로 구성·버튼 위치를 바꾼다. 일반 알림의 레이아웃 이동 문제와 구분한다. 최종 탈퇴 버튼은 Material 오류 색상이며 Enter 연속 입력으로 제출되지 않는 별도 버튼이다.

## 8. PWA·로고·캐시

- `/app-icon`은 로고 원본으로 PNG를 생성한다. 이미지 수정은 기존 로고를 임의로 재생성하지 말고 해당 렌더링 구성을 조정한다.
- 일반 아이콘은 둥근 사각형 다크 배경, maskable은 전체 다크 배경이다. 파비콘은 일반 아이콘, Apple 아이콘은 전체 배경을 사용한다.
- 배경 외부 여백은 없고 내부 로고에는 여유를 둔다. 최신 비율은 route 구현을 확인한다.
- 아이콘을 바꾸면 manifest와 layout의 아이콘 URL 버전을 함께 갱신한다. 기존 설치 앱의 아이콘 즉시 갱신은 보장하지 않는다.
- 서비스 워커는 offline 안내·로고만 저장한다. 인증 페이지·API·OAuth 콜백 응답을 캐시하지 않는다.
- 초기 설치 권장은 지원 브라우저에서만 표시한다. iOS Safari의 수동 설치 안내와 설치 여부 조회 한계를 존중한다.

## 9. 통신·배포·검증

- `Failed to fetch`는 브라우저 네트워크 실패일 수 있다. 메시지를 바꾸거나 재시도했다고 근본 원인이 해결됐다고 보고하지 않는다.
- 현재 조회 중복 방지와 네트워크 실패 시 조회 1회 재시도가 있다. 예약·취소·탈퇴 POST는 결과 불명 상태에서 자동 재시도하지 않는다.
- 페이지 prefetch는 경로 코드를 준비하는 최적화다. 최신 예약 데이터나 인증 확인을 생략하는 기능이 아니다.
- GitHub `main` 푸시와 Vercel 운영 배포를 연동하는 구성이다. **푸시 성공 ≠ 배포 성공**이다. 배포 완료를 말하려면 최신 SHA·READY·운영 도메인 연결을 확인한다.
- 자동 배포가 생성되지 않았던 사례가 있다. 배포 목록·커밋·연동 이벤트를 확인하고, 승인 없이 빈 커밋이나 연동 재설정을 하지 않는다.
- CLI 수동 배포는 로컬 작업 트리를 올린다. 최신 원격 main이라고 가정하지 말고 branch·SHA·미커밋 변경·연결 프로젝트를 확인한다.
- 이전 세션에서는 `npx --yes vercel@65.11.0`이 작동했고 구형 전역 CLI에 문제가 있었다. 현재 설치·인증 상태는 다시 확인한다.
- 운영/Preview Supabase 환경은 분리한다. `.env.local`, `.vercel/`의 전체 내용을 출력하거나 공유하지 않는다.
- 운영 `NEXT_PUBLIC_SITE_URL`과 Supabase Site URL/Redirect URLs, Google Cloud의 **Supabase OAuth callback**은 서로 다른 설정이다. README의 구분을 따른다.
- 웹 배포는 DB 마이그레이션을 자동 적용하지 않는다. DB 적용 여부를 별도로 확인한다.

검사 명령은 `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run test:e2e`다. 변경과 사용자 요청에 필요한 범위만 실행한다.

- PGlite 테스트는 단일 연결이며 실제 동시성 증명이 아니다.
- 모의 API 기반 브라우저 회원 테스트는 실제 Google OAuth 성공의 증거가 아니다.
- 타입·린트 통과를 실제 모바일 레이아웃·터치·고주사율 검증으로 표현하지 않는다.
- 과거 정적 보안 검사에서 보고된 취약점이 없었더라도 이후 코드와 실제 배포의 안전성을 보증하지 않는다.
- 테스트·보안 도구 실패는 정확한 오류와 미완료 범위를 알린다. 성공한 검사로 대체해 표현하지 않는다.

## 10. 보고와 문서 유지

최종 응답에는 변경 내용, 실제 실행한 검사, 남은 제한과 커밋/푸시 상태를 간단히 적는다. 실제 확인 없이 배포·운영 테스트를 완료했다고 쓰지 않는다.

규칙이나 운영 상태가 바뀌면 README와 관련 안내를 함께 확인한다. 이 문서는 구현에 대한 길잡이이므로 과거 설명을 그대로 따르기보다 최신 소스·마이그레이션·사용자 지시와 대조한다.
